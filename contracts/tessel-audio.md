# tessel-audio — external contract

Source: `~/tessel-bluetooth/tessel-audio/` (refs are `file:line` there). Two binaries:
- **tessel-audio** (on demand GTK app: popup, settings window, volume-key OSD) — `audio_manager.py`.
- **loopback service** (resident, ~21 MB RSS + a `pw-dump` child ~6 MB) — `loopback_service.py`. Port this first.

### loopback_service.py
- `loopback_service.py [--config PATH]` (:207). Default store `${XDG_CONFIG_HOME:-~/.config}/tessel-audio/loopbacks.json`.
- Single instance: `flock(LOCK_EX|LOCK_NB)` on `<store>.service.lock` (i.e. `loopbacks.service.lock`, mode 0600); if held → log `The loopback service is already running for this configuration.` and **exit 0** (:213-219).
- SIGINT/SIGTERM → quit loop, terminate children (≤2 s then kill) (:224, close :131-148,193-202).
- Logging: `logging.basicConfig(INFO, "%(levelname)s: %(message)s")`, logger `tessel-audio-loopbacks` → journald.
- Missing `pw-loopback` → RuntimeError at start (:159) → non-zero exit (unit restarts).

loopbacks.json (version must be int 1, keys exactly `version`,`loopbacks`; entry keys exactly `id,name,target_name,target_description`; id canonical UUID4 string; name 1–120 chars, target 1–1024, description 1–512, stripped, no C0/DEL; ≤64 entries; names unique case-insensitively; file ≤256 KiB; written `indent=2, ensure_ascii=False` + `\n`):
```json
{
  "version": 1,
  "loopbacks": [
    {"id": "3f2b…-uuid4", "name": "Stream mix", "target_name": "alsa_output.pci-0000_0c_00.4.analog-stereo", "target_description": "Speakers"}
  ]
}
```
- Directory monitored (`monitor_directory(WATCH_MOVES)`), events on basename debounced 100 ms (loopback_store.py:136-158). Invalid file → keep last valid config (service logs `<err> Keeping the last valid loopback configuration.` once per distinct error) (loopback_service.py:173-181); app shows error and does **not** overwrite malformed files.
- No other component reads/writes this file. No Global Settings keys of its own (Global Settings embeds the whole settings view, §5).

## 4. Data model / PipeWire semantics (must match exactly)
- Media classes handled: `Audio/Sink, Audio/Source, Audio/Source/Virtual, Stream/Output/Audio, Stream/Input/Audio` (audio_backend.py:24). Devices: `media.class=Audio/Device`.
- Description fallbacks: node `node.description→node.nick→application.name→node.name→"Audio stream"`; device `device.description→device.nick→device.name→"Audio device"`; icon `application.icon-name→device.icon-name→"audio-card-symbolic"` (:67-101).
- Volumes from pw-dump `Props.channelVolumes` are linear → displayed as `cbrt(v)`; node.volume = max(channel volumes) (:42-47,85-96, mixer :431).
- Defaults from metadata `default.audio.sink/source` JSON `{"name":…}` resolved by node.name (:110-117). `target.object` resolved by name, then serial (never raw id) (:118-119,137-140). Actual links override configured target (:144-166).
- Routes filtered by direction (`Output` for sinks else `Input`), by `card.profile.device`, and by active profile (:126-143).
- Internal nodes hidden: `audio.manager.loopback.internal` or `audio.manager.meter` ∈ {True,"true",1} (string "false" is NOT truthy) (:102-104, TRUE_VALUES :32).
- Writes validated against `object.serial` + bound id (stale/recycled ids rejected with "This audio device changed. Please select it again.") (:616-626). Volume range 0–1.5 (:637-641).
- Volume writes coalesced 45 ms; master `volume` drops pending `channelVolumes`; mute flushes immediately (:643-663). Echo window 0.35 s: own-write echoes update model but defer view refresh (:30,408-452,523-528). View notifications debounced 25 ms; graph applies 20 ms; snapshot start 120 ms.
- Reconnect: startup timeout 5 s → reconnect 2.5 s; core disconnected → reconnect 2 s; pw-dump exit backoff `min(10 s, 0.5 s·2^n)`, error shown after 3 failures, last graph kept (:341-345,548-559,595-600).
- `target_available(node)`: false if state `error` or active route `available=no`; suspended is available (audio_model.py:56).

## 9. Memory / startup
- Loopback service imports `audio_backend` → Wp/GObject (no GTK) ≈21 MB; it runs `pw-dump --monitor` permanently **even with zero loopbacks** (observed). Rust: zbus not needed; use libpipewire/wireplumber directly or keep pw-dump parsing; consider not monitoring when the store is empty only if behaviour (reaction to file add) is preserved.
- App: GTK4 + Wp + (lazily) Gst/level_monitor, adjustment_osd and audio_ui imported on demand; settings window built lazily. Key-only launches should paint the OSD fast (Python ~0.5–1 s cold).
