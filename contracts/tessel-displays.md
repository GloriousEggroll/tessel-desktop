## 2. IPC

### tessel-displays daemon socket (consumed) — tessel-displays:542-597
- Path: first existing of `$XDG_RUNTIME_DIR/tessel-displays.sock`, `$XDG_RUNTIME_DIR/tessel-displays.$XDG_VTNR.sock`; runtime default `/tmp`. Same lookup in `tessel-brightness/display_scaling.py:28-31`.
- `AF_UNIX SOCK_STREAM`, timeout 5 s; send `"OP: <OP>\n<yaml payload>"`; read until EOF (8192 chunks; abort > 16 MiB); YAML response.
- Ops used: `GET` (expects dict with `STATE` dict: `STATE.HEADS[]` with `NAME`, `DESCRIPTION`, `CURRENT{…VRR…}`, `DESIRED{…}`, modes, `VRR_MODE`, `VRR_CAPABLE`; `CFG` dict), `CFG_SET`, `CFG_DEL`, `CFG_WRITE`.
- Adaptive sync per head in `STATE.HEADS[]`: `VRR_MODE` = `"auto" | "always" | "off"` (from `VRR_OFF`/`VRR_ALWAYS`); `VRR_CAPABLE` = `true | false` from a wlr-output-management **test** (never applied) with adaptive sync enabled, run once per head and current mode; the key is absent while unknown (the window treats unknown as capable). `CURRENT.VRR` is whether adaptive sync is on right now; the daemon never sets adaptive sync through the protocol (`DESIRED.VRR` always equals `CURRENT.VRR`). Payload = `yaml.safe_dump({"CFG": cfg}, sort_keys=False).rstrip()`.
- CFG keys written: `MODE{desc:{WIDTH,HEIGHT,HZ(float = refresh_mHz/1000)}}`, `SCALE{desc:float}`, `AUTO_SCALE:true`, `TRANSFORM{desc:"90|180|270|FLIPPED|FLIPPED-90…"}`, `DISABLED{desc:null}`, `VRR_OFF[desc]`, `VRR_ALWAYS[desc]`, `CALLBACK_CMD`, `ORDER[names]`, `ARRANGE ROW|COLUMN`, `ALIGN TOP|MIDDLE|BOTTOM|LEFT|RIGHT`. Save sequence: `CFG_DEL del_cfg` (if any) → `CFG_SET cfg` → `CFG_WRITE` → apply XWayland primary now and again after 500 ms → refresh the Adaptive Sync drop-downs only, from `VRR_MODE`/`VRR_CAPABLE` (save_config tessel-displays:2669-~2990).
- `CFG_DEL` contents: TRANSFORM entries reset to STANDARD, DISABLED entries re-enabled, SCALE entries switched to auto, `VRR_OFF`/`VRR_ALWAYS` entries (desc and output NAME) of screens leaving that mode, `CALLBACK_CMD:""` if callback cleared.
- Adaptive Sync drop-down (Automatic, Always, Off). A screen in `VRR_OFF` is Off (also when it is in `VRR_ALWAYS` too), in `VRR_ALWAYS` is Always, in neither is Automatic (on only while an app is fullscreen on that screen; the default). Saving: Automatic → `CFG_DEL` from both lists; Always → `CFG_SET VRR_ALWAYS[desc]` + `CFG_DEL VRR_OFF[desc, NAME]`; Off → `CFG_SET VRR_OFF[desc]` + `CFG_DEL VRR_ALWAYS[desc, NAME]`. Both lists are sent only for *changed* monitors (CFG_SET adds members; sending a full list would change back monitors changed in another editor). The 10 second revert removes what Apply added to either list and sets the previous lists again. Default (unedited) STANDARD transform is removed, `FLIPPED-STANDARD` → `FLIPPED`.
- Matching a screen to a per-screen entry (ORDER, MODE, SCALE, TRANSFORM, DISABLED and its PLUGGED/UNPLUGGED conditions, VRR_OFF, VRR_ALWAYS), daemon `components/displays/src/daemon/layout.rs`:
  1. way-displays' rules: the connector name or the full description, exactly; `!<regex>` against either; a case-insensitive part of either.
  2. **Tessel only (not in way-displays): the same monitor on another connector.** An entry `"<identity> (<connector>)"` (wlroots' description form; `<connector>` is one to three letter-first alphanumeric groups joined by `-`, then `-` and up to five digits, e.g. `DP-2`, `HDMI-A-1`, `eDP-1`, `USB-C-1`, `HEADLESS-1`) matches a screen whose description is `"<identity> (<its NAME>)"` with byte-identical `<identity>` (make, model, serial as wlroots prints them, double spaces included). Never when the screen has neither a make nor a model (no EDID: wlroots prints `(null) (null)`; also `Unknown`), when another connected screen's description has the same `<identity>` (identical monitors without distinct serials), when a connected screen has the entry's description, or for an entry starting with `!`. DRM connector numbers change with driver load order (two GPUs) and when a cable moves, which is what this covers.
  - Rule 1 always wins over rule 2, whatever the order in the file. Maps (MODE, SCALE, TRANSFORM): the first entry by rule 1, else the **last** entry by rule 2. DISABLED: all entries by rule 1, else the last by rule 2. Adaptive sync: VRR_OFF/VRR_ALWAYS by rule 1 (Off wins), only if neither list matches by rule 1 the same by rule 2. ORDER: a fourth pass after exact, regex and partial. PLUGGED/UNPLUGGED: either rule counts. The adaptive sync block in rc.xml is written for the current connector names, so it follows.
  - The Displays window reads the same way (`model::resolved_cfg`: a screen that no entry matches by rule 1 shows the rule 2 entry as if saved under its description). On Apply it saves the screen under its current description and `CFG_DEL`s that screen's rule 2 entries in MODE, SCALE, TRANSFORM and DISABLED (keeping the value under the current description where Apply sets none), and in VRR_OFF/VRR_ALWAYS when its adaptive sync choice changed. Entries of screens not connected, connector names, regexes and partial names are never removed this way. ORDER is replaced from the arrangement as before.
- Callback/notify switch: default `notify-send "tessel-displays ${CALLBACK_LEVEL}" "${CALLBACK_MSG}"`; immediate `CFG_SET {CALLBACK_CMD}` on edit, `CFG_DEL {CALLBACK_CMD:""}` when cleared (2515-2562).

### D-Bus (consumed): `org.tessel.BrightnessManager` (session)
Object `/org/tessel/BrightnessManager`, iface `org.tessel.BrightnessManager.Controls`: `GetState()→s(JSON)`, `Refresh()→b`, `SetValue(s connector, s feature, d value, s expected_id)→b`, `SetAutoDim(b)→b`, `SetScale(s,d,s)→b`, `SetAutoScale(b)→b`, `SetSettings(s JSON)→b`, signal `Changed(s JSON)`. Via `tessel-brightness/brightness_client.py` loaded by path (repo sibling, then `~/.config/waybar/scripts/tessel-brightness/brightness_client.py`) (tessel-displays:741-760). Features used: `brightness`, `contrast`; auto-dim switch + settings (dim %, durations). Slider writes are coalesced: the first change is sent after 100 ms (later changes do not push it back), at most one write per feature is in flight, and the newest value is sent as soon as the previous one is confirmed (value matches after rounding, the service went busy and back, a new error, or 3 s without any sign / 15 s busy). Until then, and while the pointer is held, the handle and label show the user's value and the slider stays sensitive; busy without a write of ours, HDR lock, a disabled/missing display or a not-ready service still disable it. Keyed by display `id` (expected_id) so hotplug identity change cancels (BrightnessControls 761-998; the Python original debounced 180 ms and reset the handle to the old value while the write ran, issue #10).

### Wayland
- `zwlr_layer_shell_v1` via gtk4-layer-shell (`CDLL('libgtk4-layer-shell.so', RTLD_GLOBAL)` before GTK): `MonitorOverlay` identify labels — layer **OVERLAY**, exclusive zone **-1** (ignore panels; sits at output 0,0), anchor TOP+LEFT, keyboard NONE, `set_monitor(monitor)`, empty input region (`cairo.Region()`) → click-through (600-740, 2177-2232). Monitor matched by `desc in GdkMonitor.description`.
- The window uses no wlr-output-management: all output changes go through the daemon.

## 7. Risks
- Global Settings imports the Python module and pokes internals (`CONFIG_DATA`, `TesselDisplaysApp(embedded=True)`, title widget tree). Until GS is Rust, keep the Python GUI installed or expose an embeddable widget from a Rust GS.
- Exact managed-block text (env, xinitrc, rc.xml HDR/adaptive sync/colour) is parsed by tessel-dock and by the next GUI run — byte-compatible output required.
- YAML round-trip with the daemon (`sort_keys=False`, `HZ` float, `DISABLED{desc: null}`).
- Protocols: layer-shell only (gtk4-layer-shell crate is enough); empty input region via `gdk::Surface::set_input_region`.
