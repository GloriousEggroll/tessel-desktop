# keep-awake — external contract

Python source: `~/btmanager/keep-awake/` (refs are `file:line` relative to it unless prefixed).
Role: resident manual idle/sleep inhibitor (logind `idle:sleep` block FD) + a small layer-shell popup.
~730 LOC runtime. Baseline RSS ≈ 27 MB (all GTK, though the daemon itself needs only D-Bus).

## 2. IPC

### 2.1 D-Bus owned (session bus)
- Name `org.waybar.KeepAwake` (GApplication), object `/org/waybar/KeepAwake` (+ standard `org.gtk.Application`, `org.gtk.Actions`, `org.freedesktop.Application`).
- Interfaces registered on the app object path via `shared/service_settings.py` `SettingsService` (`keep_awake.py:82-88`):

| Interface | Member | Signature | Semantics |
|---|---|---|---|
| `org.waybar.KeepAwake.Controls` | `GetState()` | `→ s` | JSON of `status()` |
| | `SetEnabled(b)` | `b → (b ok, s error)` | `ok = not backend.error`, error = backend.error (`:141-143`); then emits `Changed` |
| | signal `Changed` | `s` | JSON of `status()`; emitted on every backend change (`:130-134`) and after each Set call |
| `org.waybar.KeepAwake.Duration` | `GetState()` | `→ s` | same JSON |
| | `SetDuration(u)` | `u minutes → (b, s)` | minutes ∈ {30,60,120,0}; else D-Bus error `org.waybar.KeepAwake.Duration.Error` "Unsupported Keep Awake duration." |
| | signal `Changed` | `s` | same JSON, emitted on this interface too |
- Errors: `TypeError/ValueError/RuntimeError/OSError` → `return_dbus_error(<interface>.Error, str(e))` (`shared/service_settings.py:28-39`).
- Clients must call with `NO_AUTO_START`, 15 s timeout (`shared/service_settings.py:139`).

### 2.2 D-Bus consumed (system bus) — `keep_awake_backend.py`
| Call | Detail |
|---|---|
| `bus_watch_name_on_connection("org.freedesktop.login1")` | appear → ready, (re)acquire if requested; vanish → close FD, ready=false, error "System power management is unavailable." (`:60-82`) |
| `org.freedesktop.login1.Manager.Inhibit(ssss) → h` on `/org/freedesktop/login1` | args exactly `("idle:sleep", "Keep Awake", "Keep this desktop awake until turned off", "block")`, `NO_AUTO_START`, 10 s timeout, with unix-fd list (`:118-132`). FD set non-inheritable and held; closing it releases. |
| bus `closed` | treat as vanish, detach, retry `bus_get` every 2 s (`:84-97`). Bus-get failure error: "System power management is unavailable: <msg>". |

### 2.3 `status()` JSON (`keep_awake.py:43-58`) — used by `--status`, `GetState`, `Changed`
```json
{"text": ""|"", "tooltip": "...", "duration": 0, "until": 1730000000.0|null,
 "class": "active"|"unavailable"|"pending"|"inactive",
 "active": bool, "ready": bool, "requested": bool, "pending": bool, "error": ""}
```
- `pending = requested && !active`; class precedence: active > unavailable(!ready) > pending > inactive.
- tooltip: `tr("Keep Awake: {value1}")` with value1 = literal **"Active"** (NOT translated — quirk) / `tr("Turning on…")` / `tr("Inactive")`; then `\n`+error, or if active `\nAutomatic dimming, display off, and sleep are paused.` (untranslated); then `\nClick for controls · Right-click to toggle` (untranslated).
- `until` only reported while `requested`; `duration` always.

## 4. Behaviour (state machine)
- Each service start defaults OFF **unless** an unexpired `until` exists in timer.json → auto `set_enabled(True)` and reschedule (`:265-270`). "Until turned off" (duration 0) is NOT restored across restarts (until=null).
- `TimedBackend.set_enabled(True)`: `until = now + duration*60` (or null if 0), save, schedule; False: until=null, save (`:272-279`).
- `set_duration(m)`: validate; if requested, recompute until from *now*; save; schedule; notify (`:284-293`).
- Timer: `timeout_add_seconds(max(1, min(60, until-now+1)))`; wall-clock re-check (covers suspend). On expiry → `set_enabled(False)`; if backend no longer requested → forget until & save (`:301-319`).
- Acquire generation counter: late replies from cancelled/older requests are finished and their FD closed; never kept if disabled meanwhile (`:139-163`). Failure → `requested=False`, error "Could not keep the desktop awake: <e>".
- Owner change of logind (new unique name) → drop old FD and re-acquire if requested (`:60-72`).
- Disable while ready clears error.

## 10. Parity test cases (port these)
From `test_keep_awake.py` / `test_keep_awake_ui.py`:
1. Duration sets & persists end time, then releases at expiry (`:49`).
2. Unexpired timer resumes on restart; expired one does not (`:61`).
3. "Until turned off" has `until=null`; unknown durations rejected (`:73`).
4. FD held only after Inhibit reply; closed on disable (`:127`); real FD transfer released on disable — pipe reader sees EOF (`ui:117`).
5. Disabling a pending request: late reply cannot re-acquire; its FD is closed (`:145`).
6. Rapid toggles: only the latest request counts (`:155`).
7. logind loss closes FD; reappearance re-acquires only if still requested (`:167`).
8. Denied Inhibit → toggle reset (requested=false), error surfaced (`:185`).
9. Enabling before logind is ready queues intent (`:197`); immediate bus failure doesn't leave pending (`:205`).
10. Shutdown releases FD and late replies; timer state not persisted on shutdown (`:214`).
11. Secondary (launcher) instance never builds a backend; `--toggle` with no primary exits ≠0 (`:231`, `ui:107`).
12. `status()` class/pending/active/unavailable truth table, icon `` when active (`:237`).
13. `--enable/--disable/--toggle` never open popup (`:248`).
14. Singleton popup: `--popup --popup-edge top --popup-offset 45`, dismiss keeps state, CLI disable reflected in switch, duration dropdown index 0→30 min shows "On until", index 3 → until null; unavailable → switch insensitive (`ui:67`).

## 11. Memory / startup notes
- Daemon path needs only gio + system bus + one FD. GTK is imported at module top (`keep_awake.py:20-22`); popup module imported lazily (`:118`). Rust: init GTK lazily on first popup if feasible (gtk4-rs `Application` still needs `gtk::init` before windows; consider `gio::Application` primary + on-demand GTK init) to beat 27 MB.
- Startup is async (bus_get); `--status` immediately after start may report `ready:false`.

## 12. Riskiest parity points
1. Callers invoke `/usr/bin/python3 …/keep_awake.py <flag>` and talk GApplication command-line forwarding — Rust primary must keep app-id `org.waybar.KeepAwake` and GApplication CommandLine semantics (incl. remote stdout printing for `--status` and launcher-only failure), or a Python shim must remain at that path.
2. Exact `status()` JSON keys/classes/untranslated literals and `Changed` on BOTH interfaces.
3. FD lifecycle races (generation counter, stale replies, owner change) and timer.json restore semantics.
